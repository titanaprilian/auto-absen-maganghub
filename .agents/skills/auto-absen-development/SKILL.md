# Auto Absen MagangHub Development

Use this skill for code changes in this repository. Treat attendance submission and notification delivery as external side effects, not ordinary local commands.

## Orient before editing

- Read the relevant code and tests first. The CLI entry point is `main.py`; command behavior lives in `app/commands.py`; configuration is loaded in `app/config.py`; authentication and API access are in `app/auth/` and `app/api/`; attendance and holiday logic are in `app/models/`; timezone and notifications are in `app/utils/`.
- Check the target runtime before changing schedules. Linux/VPS cron is generated by `setup_cron.sh`; GitHub schedules are in `.github/workflows/`; Vercel endpoints are in `api/` and scheduling is configured by `vercel.json`. These schedules are independent, so do not assume changing one updates the others.
- Check `.env.example` and the relevant configuration code for setting names. Never print, copy into source, or commit real `.env` values or credentials.
- Keep changes focused and follow existing Python patterns. Dependencies are declared in `pyproject.toml` and `requirements*.txt`; do not add a dependency if the standard library or an existing package suffices.

## Protect live behavior

- Do not run `python main.py absen`, `python main.py remind`, a scheduler setup script, a deployed cron endpoint, or a workflow that can contact external services unless the user explicitly asks for that exact action.
- `python main.py absen --dry-run` is the supported payload-only check: `cmd_dry_run` validates configuration and prints the payload without network access. Do not substitute `absen` without `--dry-run`.
- Prefer isolated unit tests with fake services and mocked HTTP calls. Do not use live credentials or production accounts in tests.
- Preserve safeguards around already-recorded attendance, weekends/holidays, retryable failures, and WIB time handling. When changing one, add or update behavior-focused tests for the affected case.

## Validate

- Run focused tests first, then the full suite when practical: `python -m pytest` (development dependency: `pytest`).
- For CLI or configuration changes, run non-submitting checks such as `python main.py --help` or `python main.py doctor` only when their behavior and environment are appropriate. `doctor` can inspect local configuration; avoid exposing its output if it includes private details.
- Review the diff and confirm no credentials, `.env`, logs, or unrelated files were added.
- Report any tests not run and why. Never claim a live attendance path was verified by a unit test or dry run.
